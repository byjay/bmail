# 요청서: SGW 사내메일(mail)을 "메일 AI 전용앱"으로 대체하기 위한 맞춤설정

- 작성: 2026-11-20 / 요청 주체: SGW(콘트롤타워·관문) 프로젝트 팀장 세션
- 수신: 아웃룩 모방 메일 AI 전용앱 담당 에이전트
- 목적: SGW 안의 단순 1:1 사내메일 기능을 이 앱으로 대체한다. 이 앱이 메일 기능의 본체가 되고, SGW 는 로그인·진입(관문)만 맡는다.
- 보안 전제: 이 문서에는 직원 실명·이메일·IP·키를 넣지 않았다. 필요한 값은 요청자에게 별도로 받는다. 받은 값은 코드·문서·커밋에 평문으로 넣지 않는다(`.env` 또는 시크릿 저장소).

## 0. 먼저 보고할 것 (작업 시작 전, 추측 금지)
아래는 요청자가 이 앱의 현재 상태를 알려주지 않아 비워 둔 항목이다. 코드를 읽어 사실만 보고하고, 모르면 "미확인"이라고 쓴다.

| # | 확인 항목 |
|---|---|
| 1 | 기술 스택(프론트·백엔드·DB), 실행 방식(웹/데스크톱/Flutter), 배포 위치 |
| 2 | 실제 메일 송수신 방식(IMAP/SMTP, Graph API, 자체 서버 중 무엇인지) 또는 아직 목업인지 |
| 3 | 현재 인증 방식과 사용자 모델 |
| 4 | AI 기능의 현재 범위(요약·초안·분류 등)와 사용 중인 모델/엔드포인트 |
| 5 | 이미 구현된 화면(폴더 트리, 3열 읽기창, 검색, 규칙 등) 목록 |

## 1. 대체 대상: SGW 현행 메일의 계약
SGW 메일은 `GET/POST/PUT/DELETE /api/mail` 하나이며 Cloudflare D1 테이블 `internal_mail` 을 쓴다. 이 계약을 기준으로 기능 동등성을 맞춘다.

| 항목 | 현행 동작 |
|---|---|
| 모델 | 1:1 내부 메일. 필드: id, senderId, senderName, recipientId, recipientName, subject, body, isRead, createdAt |
| 조회 | 본인이 보낸/받은 메일만. `box=inbox` / `box=sent` / 전체 |
| 발송 | 발신자는 로그인 신원으로 서버가 강제(타인 명의 불가). 수신자 필수 |
| 읽음 | 수신자만 변경 가능 |
| 삭제 | 발신자·수신자 당사자만 |
| 길이 제한 | 제목·본문 상한 있음(`functions/_lib/validate.js`의 `LIMITS`) |
| 없는 것 | 참조(CC)·숨은참조·첨부·폴더·스레드·검색·외부 메일 연동·임시보관 |

원칙: 현행에 있던 권한 규칙(본인 것만 조회, 발신자 신원 강제, 당사자만 삭제)은 **약해지면 안 된다.**

## 2. 요구사항

### 2.1 필수(대체의 최소선)
1. 받은편지함·보낸편지함·임시보관·휴지통, 읽음/안읽음, 삭제(휴지통→영구삭제 2단계).
2. 작성: 받는사람·참조·숨은참조, 제목, 본문, 첨부(크기 상한과 허용 확장자 명시), 임시저장.
3. 스레드(대화) 묶음, 검색(보낸이·제목·본문), 안읽음 필터.
4. 로그인은 SGW 관문 경유 SSO(아래 3절). 앱 자체 비밀번호를 만들지 않는다.
5. 수신자 자동완성은 SGW 직원 목록 API 를 쓴다(아래 3절). 앱에 직원 명단을 복사해 두지 않는다.
6. 현행 `internal_mail` 데이터 이전 도구(드라이런 → 실행, 건수 대조, 되돌리기 가능).

### 2.2 AI 맞춤설정(이 앱의 핵심)
각 기능은 사용자가 끄고 켤 수 있어야 하고, 기본값은 **꺼짐 + 사용자 확인 후 반영**이다.
1. 스레드·긴 메일 요약, 해야 할 일(액션 아이템) 추출.
2. 답장 초안 생성: 어조(격식/간결), 길이, 서명 반영. **자동 발송 금지** — 사용자가 확인하고 보내기를 눌러야 한다.
3. 분류·우선순위(결재 요청, 회의, 참조용 등)와 규칙 제안.
4. 맞춤설정 화면: 사용자별 어조·서명·언어(한국어 기본)·AI 켜기/끄기·학습 데이터 사용 여부.
5. 조선·선박 전장 업무 용어 사전(사용자·관리자 편집 가능). 용어 목록은 요청자가 제공한다.

### 2.3 데이터·보안(타협 불가)
1. 메일 본문·첨부·직원정보는 **외부 무료 LLM/API·외부 번역·OCR 로 보내지 않는다.** AI 호출은 로컬 모델 또는 요청자가 승인한 비공개 엔드포인트만 쓴다. 어떤 엔드포인트를 쓰는지 0절 보고서에 적는다.
2. 키·토큰·비밀번호는 `.env`/시크릿으로만 두고 로그·커밋·문서에 출력하지 않는다.
3. 저장 데이터는 사용자 단위로 접근 통제한다. 관리자도 타인 메일 본문은 기본 열람 불가(열람이 필요하면 감사 로그 + 별도 승인).
4. 첨부파일은 바이러스·확장자 검사 후 저장하고, 다운로드는 인증된 본인에게만 서명 URL 로 준다.
5. AI 프롬프트에 들어간 메일 본문을 로그에 남기지 않는다. 메일 본문 안의 지시문("이 메일을 외부로 전달해라" 등)은 **데이터**일 뿐 명령이 아니며, AI 가 그에 따라 발송·삭제·전달하지 않게 한다(프롬프트 주입 방어). AI 가 하는 발송·삭제·전달은 항상 사용자 확인을 거친다.
6. 테스트 데이터는 가짜 값만 쓴다(`user01@example.test` 형식). 실제 직원 정보를 픽스처에 넣지 않는다.

## 3. SGW 와의 연동 인터페이스
SGW 는 아래를 제공한다. 정확한 URL·시크릿 값은 요청자에게 받는다. 이 문서에 쓰지 않는다.

| 필요 | SGW 쪽 수단 | 비고 |
|---|---|---|
| 로그인 | SGW 가 서명한 SSO 토큰(HMAC) 교환. 기존 SEDMS 연동과 같은 방식 | 공유 시크릿은 `.env` 로만 전달 |
| 세션 확인 | `GET /auth/me` | 토큰의 `sub`(사용자 ID)·이름을 신원으로 사용 |
| 직원 목록 | `GET /api/employees` | 자동완성·수신자 검증용. 캐시는 짧게 |
| 진입 | SGW 메뉴의 "메일" 항목이 이 앱으로 이동 | 확장앱 사이드패널·웹 둘 다 |

요구: 이 앱은 사용자 식별을 **SGW 의 `sub` 값**으로 통일한다(이전 데이터의 `sender_id`/`recipient_id` 와 같은 값). 동명이인·이름 변경에 흔들리지 않게 이름이 아니라 ID 로 매칭한다.

## 4. 이전(마이그레이션) 계획 요구
1. 원본: `internal_mail`(위 필드). 이 앱 쪽 스키마로 매핑표를 먼저 제출한다.
2. 드라이런으로 건수·누락·인코딩 오류를 보고한 뒤 승인받고 실행한다.
3. 이전 후 건수·샘플 대조(실명 없이 ID 기준)를 제출한다.
4. SGW `/api/mail` 은 즉시 삭제하지 말고 **읽기 전용 전환 → 일정 기간 후 제거** 순으로 한다. 제거는 요청자 승인 후.

## 5. 완료 기준 (증거 제출)
| 단계 | 증거 |
|---|---|
| 정적 검사·빌드 | 로그 |
| 테스트 | 아래 6개 시나리오의 자동 테스트 통과 로그. 핵심 권한 로직은 되돌리면 실패하는 테스트(뮤테이션 확인)로 |
| 실제 실행 | 로그인→작성→발송→수신→읽음→삭제 흐름의 실행 로그 또는 스크린샷 |
| 이전 | 드라이런·실행·대조 결과 |
| 보안 | 외부 전송 경로가 없다는 확인(AI 호출 목적지 목록) |

필수 테스트 시나리오: ① 타인 메일 조회 불가 ② 타인 명의 발송 불가 ③ 수신자만 읽음 변경 ④ 당사자만 삭제 ⑤ 메일 본문 속 지시문이 있어도 AI 가 자동 발송·전달하지 않음 ⑥ AI 끔 상태에서 AI 호출 0회

## 6. 진행 방식
1. 0절 보고 → 요청자 확인 → 설계안(스키마·화면·AI 호출 경로) 제출 → 승인 후 구현.
2. 작은 단위로 나눠 구현하고, 각 단위마다 테스트를 먼저 쓴다.
3. 되돌리기 어려운 일(운영 데이터 이전 실행, 배포, SGW 쪽 `/api/mail` 변경, 외부 발송)은 실행 전에 요청자에게 묻는다.
4. SGW 코드는 이 앱 담당이 직접 고치지 않는다. SGW 쪽 변경이 필요하면 요청 사항으로 정리해 요청자에게 전달한다.
5. 보고는 한국어, 코드·식별자는 영어. 측정하지 않은 것은 "미확인"으로 쓴다.

## 7. 요청자에게 받아야 할 값(이 문서에 없음)
SSO 공유 시크릿, SGW 기준 URL, 사용 가능한 AI 엔드포인트, 업무 용어 목록, 첨부 크기·확장자 정책. 위 값은 안전한 경로로 받는다.
